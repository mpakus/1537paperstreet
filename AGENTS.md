# AGENTS.md — правила для AI-агентов

Проект: **1537paperstreet**, локальный Markdown-ридер и редактор для macOS, Linux и Windows на Rust + Tauri 2 + Svelte 5.
Читать перед началом любой задачи. Вместе с `PLAN.md` (архитектура) и `CHECKLIST.md` (задачи).

**Текущий продукт — ридер с редактором.** В окне есть Preview / Edit / Split, атомарное сохранение, Format, чекбоксы задач в превью и живое превью Split из буфера редактора (`doc_preview`). Это превью не заменяется целиком: `patchPreviewHtml` (`ui/src/lib/preview-patch.ts`) оставляет блоки с тем же `data-hash`, чтобы скролл и уже нарисованные диаграммы не прыгали. Клик по пункту оглавления в Split скроллит и превью, и редактор к строке `data-src-line` (`sourceLineForHeading`, `MarkdownEditor::scrollToLine`). В режиме Preview редактор не скроллить. Фазы P0–P8, P11 и P16 реализованы. Открытые пункты P9 в `CHECKLIST.md` (черновики, автосохранение, инкрементальный рендер, найти-и-заменить) **не доделывать**, пока пользователь явно не попросит. Клиентский патч блоков — не замена `render_incremental` (T-167, T-184). P10 (история) и P12 (ZIP-экспорт) **не начинать**, пока пользователь явно не попросит.

## 1. Порядок работы над задачей

1. Взять задачу из `CHECKLIST.md`. Проверить, что все зависимости `(← T-xxx)` закрыты.
2. Прочитать соответствующий раздел `PLAN.md`. Если задача противоречит плану — **остановиться и спросить**, не решать самостоятельно.
3. Ветка: `task/T-xxx-short-name`, например `task/T-080-tree`. Не копировать номер чужой задачи.
4. Сначала тест, потом код. Для задач, помеченных 🔒, тест обязателен до реализации.
5. Пометить задачу `[~]` в `CHECKLIST.md` при старте, `[x]` — в PR, который её закрывает.
6. PR закрывает **ровно одну** задачу. Несколько задач на одной ветке — только если пользователь явно просит продолжать на текущей ветке; `[x]` всё равно ставится в отдельном PR на задачу.

## 2. Definition of Done

Задача не закрыта, пока не выполнено всё:

- [ ] `cargo fmt --all --check` — чисто
- [ ] `cargo clippy --workspace --all-targets -- -D warnings` — ноль предупреждений
- [ ] `cargo test --workspace` — зелёный
- [ ] `npm run check && npm run lint && npm run test` — зелёный
- [ ] Публичные элементы задокументированы (`missing_docs` не срабатывает)
- [ ] Критерии приёмки из текста задачи выполнены и проверены
- [ ] Если задача влияет на производительность — замер приложен к PR
- [ ] Если задача трогает запись файлов — round-trip-тест «открыл и сохранил без правок ⇒ файл побайтово не изменился» проходит
- [ ] Если задача добавляет разрушительную операцию — снимок `pre_*` сделан до неё, и на это есть тест
- [ ] Если поменялся публичный API или поведение — обновлены `CHANGELOG.md` и затронутые доки
- [ ] Если принято архитектурное решение — добавлен ADR в `docs/adr/`

После изменения IPC-типов: `UPDATE_TS_BINDINGS=1 cargo test -p ps-core --test typescript` и закоммитить `ui/src/lib/generated/core.ts`.

## 3. Правила для Rust-кода

**Запрещено:**

- `unwrap()`, `expect()`, `panic!` в библиотечном коде (`ps-core`, `ps-render`). В тестах — можно.
- Блокирующий I/O в потоке команд Tauri — только через `spawn_blocking`.
- Работа с **путями проекта** в обход `fsops::resolve`. Это единственная дверь в файловую систему проекта.
- Новая зависимость без обоснования в PR-описании. Правило: одна зависимость — одна ясная причина.
- `unsafe` без комментария `// SAFETY:` и одобрения в ревью.

**Исключение для путей.** `save_user_file` пишет на абсолютный путь, выбранный в нативном диалоге Save: только `.png` / `.svg` / `.pdf`, родительская папка должна существовать, запись атомарная (temp → fsync → rename). Это **не** путь проекта и не замена `fsops::resolve`. PDF документа собирается из HTML превью через `WKWebView` (`export_pdf`) и доступен на macOS. Linux (`.deb`) и Windows (NSIS) собираются тем же релизным тегом; на них экспорт PDF сообщает, что он доступен на macOS.

**Обязательно:**

- Ошибки — через `thiserror`, единый тип на крейт. Сообщения об ошибках пишутся для пользователя, а не для разработчика.
- Любая запись в файл пользователя — атомарная: temp в той же директории → `fsync` → `rename`. Прямая запись поверх существующего файла запрещена без исключений.
- Любая операция, которая может уничтожить пользовательский текст, сначала делает снимок в историю. Девять точек перечислены в `PLAN.md` § 10.3 — новая разрушительная операция означает десятую точку, а не исключение.
- Перед записью документа сверяется `base_hash`. Расхождение = конфликт, а не повод перезаписать.
- `ps-core` и `ps-render` не импортируют `tauri`. Никогда. Это проверяется в CI.
- Команды в `ps-app` — тонкие: распаковать аргументы, вызвать core, вернуть. Если в команде появилась логика — её место в core.
- Тесты файловой системы — только на `tempfile`. Никаких обращений к реальному `$HOME`.
- Публичные типы, пересекающие IPC-границу, экспортируются в TypeScript через генератор. Ручное дублирование типов — ошибка ревью.
- Логи (`ps-core::log`) не содержат текст документов и **не содержат текст промптов Assistant**. Только действия, пути служебных файлов, ошибки.
- CSS тем генерируется в Rust (`themes_css`). JSON тем — kebab-case токены; IPC `ThemeInfo` — camelCase. UI не собирает карту токенов сам.
- `window.show_in_dock` (по умолчанию true, только macOS), `window.diagram_w` / `diagram_h` / `diagram_zoom` (896×576, zoom 1), `window.diagram_x` / `diagram_y` (null = центр), `files.show_hidden` (по умолчанию true), `viewer.preview_*` (пусто / `0` = тема), `viewer.show_toc` и `agents` добавляются в `config.json` без bump `schema_version`.
- Точка несохранённого файла — токен `--dirty` в `ui/src/styles/tokens/tokens.css`. В JSON тем его не добавлять: пользовательские темы должны грузиться без этого поля.
- Кэш Mermaid: ключ = blake3(`source_hash + "\0" + theme_id`); хеш — 64 hex-символа; `theme_id` — slug (ASCII-буквы, цифры, дефис). Не-SVG и файлы > 2 MB отклоняются.
- Codex: spawn `codex app-server --stdio` (пресет Codex или `command` basename `codex` с args `["acp"]`). Это не `codex acp` (TUI). Диалект `AgentWire::CodexApp`. `login_path()` дополняет PATH (`~/.local/bin`, Homebrew и т.п.).
- История промптов Assistant (`PromptHistory` / `agents/prompts.json`) — не P10 (история документов). IPC: `agent_prompt_history`, `agent_prompt_history_remove`, `agent_prompt_history_clear`. Удаление — явное действие пользователя, снимок `pre_*` не требуется.

## 4. Правила для фронтенда

- UI ничего не вычисляет. Форматирование, сортировка, фильтрация, парсинг — в Rust.
- Никаких CSS-in-JS и UI-фреймворков поверх Svelte. Только CSS-переменные и обычный CSS.
- Цвета берутся **только** из токенов темы. Ни одного хардкоженного hex-значения в компонентах. Исключение: `viewer.preview_bg` / `preview_fg` из `config.json` — пользовательские цвета чтения, пустая строка снова берёт `--bg` / `--fg`.
- Списки длиннее 100 элементов — обязательно виртуализированы.
- IPC только через `ui/src/lib/ipc.ts`. В тестах — `ui/src/lib/ipc.mock.ts`. Молчаливый `catch {}` — ошибка ревью.
- Ошибки IPC обрабатываются и показываются пользователю.
- Никаких сетевых запросов. Все ассеты — локальные. Mermaid и KaTeX — pinned npm + dynamic import, без CDN. Точка входа Mermaid — `ui/vendor/mermaid.esm.min.mjs`.
- Overlay-титлбар на macOS: полная полоса `--titlebar-h` (52px) сверху окна; drag-регион — внутренний элемент с `data-tauri-drag-region` и `-webkit-app-region: drag`, чтобы полоса не выпадала из потока. Слева `--traffic-pad` (88px) под traffic lights, затем Preview / Edit / Split / Search / Save / Format / Export / Board / AI. Текст заголовка в полосе не показывается (`hiddenTitle`); `setWindowTitle` по-прежнему ставит имя для Mission Control. Интерактивные контролы — `no-drag`. Linux и Windows используют обычную рамку окна; та же полоса команд остаётся. `window.show_in_dock` действует только на macOS.
- Тема: UI ставит только атрибут `data-theme`. Переключение ⌘⌥T использует сессионный `forcedThemeId` и **не** меняет пару `theme` / `theme_dark` в конфиге.

**Исключения из «логика в Rust»:**

1. Текстовый буфер редактора — CodeMirror (ADR-008), P9.
2. Ленивый клиентский рендер уже санитизированных шаблонов Mermaid и KaTeX (`IntersectionObserver`, `rootMargin: 400px`, `securityLevel: 'strict'`). Исходник, BLAKE3-хеш и HTML приходят из `ps-render`.
3. Презентационные хелперы: плоский список строк дерева и подсветка поискового запроса в `ui/src/lib/tree.ts` и `text.ts`; язык редактора по расширению в `ui/src/editor/language.ts`; список форматов Settings в `ui/src/editor/formats.ts`; аккорды отправки промпта Assistant в `ui/src/lib/keys.ts`; патч уже санитизированного HTML превью по `data-block` / `data-hash` и чтение `data-src-line` для прокрутки редактора. Без парсинга Markdown и без работы с путями на диске.
4. Маркер Preview / Split: захват DOM-выделения и сопоставление с временными санитизированными `data-ps-map` в `ui/src/lib/highlights.ts`. Разбор Markdown, валидация hex и изменение исходника — в `ps-render::markers`; сохранение — обычный `doc_save`. Пользовательский hex допустим как цвет маркера, готовая палитра берётся из CSS-токенов. ADR-012.

## 5. Производительность

Каждый PR, затрагивающий горячий путь (старт, открытие документа, скролл, поиск, дерево), должен содержать замер до/после.

Горячие пути и их бюджеты — в `PLAN.md` § 1.2. CI автоматически ловит регресс > 10 % относительно `benches/baseline.json`.

Если задача требует превысить бюджет — это не повод превысить бюджет. Это повод открыть обсуждение.

## 6. Безопасность и сохранность данных

**Главное правило проекта: пользовательский текст не теряется. Никогда, ни при каких обстоятельствах.**
Любой PR, затрагивающий `docio`, `drafts`, `history` или автосохранение, требует теста на потерю данных — не «теста, что работает», а теста на сценарий сбоя.

- Пользовательский Markdown — **недоверенный ввод**. Санитайзинг обязателен, если `allow_raw_html` выключен.
- Любой путь из UI проверяется на выход за корень проекта на стороне Rust. Проверка во фронтенде не считается проверкой.
- `asset://` scope ограничен корнями зарегистрированных проектов.
- Секреты и сертификаты — только в GitHub Secrets.
- Ноль исходящих запросов, кроме опциональной проверки обновлений.

## 7. Стиль

- Код, комментарии, имена, коммиты, ADR — **на английском**.
- `PLAN.md`, `CHECKLIST.md`, `AGENTS.md` — **Russian**; README, CONTRIBUTING,
  CHANGELOG, and the mdBook user guide (`docs/src/`) — **English**. The app UI
  is English (localization is backlog).
- Коммиты — Conventional Commits: `feat(core): add atomic json store`.
- Имена: `snake_case` в Rust, `camelCase` в TS, `kebab-case` для файлов CSS и Svelte-компонентов в `PascalCase`.

## 8. Когда остановиться и спросить

Не додумывать. Остановиться и задать вопрос, если:

- Задача противоречит `PLAN.md`.
- Требуется новая зависимость больше ~500 KB.
- Требуется изменить схему `projects.json` или `config.json`.
- Требуется изменить что-либо в пути записи файлов (`docio`, `drafts`, `history`, автосохранение) способом, не описанным в `PLAN.md` § 9.3 и § 10.
- Появляется желание завести счётчики ссылок в хранилище истории вместо mark-and-sweep.
- Инкрементальный рендер расходится с полным, и есть искушение «просто подправить ожидаемое значение теста».
- Требуется добавить сетевой запрос.
- Бюджет производительности недостижим выбранным подходом.
- Задача выглядит так, будто её нужно разбить на несколько.
- Обнаружена проблема безопасности.
- Хочется начать историю версий или ZIP-экспорт без явной просьбы.

Лучше один вопрос, чем один тихо сломанный инвариант.

## 9. Что не делать по своей инициативе

Список из `PLAN.md` § 18 — не входит в текущий продукт. Редактор и экспорт PDF уже есть. Если возникло желание «заодно сделать панель истории», ZIP-экспорт, автосохранение, черновики или инкрементальный рендер — не надо, пока пользователь явно не попросит.

## 10. Карта кода

- `ps-core`: `config`, `agents`, `dashboard`, `projects`, `fsops`, `tree`, `watch`, `docio`, `log`, `themes`, `mermaid_cache`, `ui_state`, `search`, `store`, `paths`, `updates`
- `ps-app`: тонкие IPC-команды, overlay-окно, нативное меню, `asset://`, `WatchHub`, `save_user_file`, ACP-хост (включая Codex app-server)
- `ui`: панели Svelte 5 (`Projects`, `Tree`, `Preview`, `Settings`, `QuickOpen`, `QuickSwitch`, `ContentSearch`, `FindBar`, `Conflict`, `About`, `Assistant`, `Dashboard`, `ChromeToolbar`). Живое превью Split — `ui/src/lib/preview-patch.ts`. Строка исходника для оглавления — `ui/src/lib/toc.ts`.
- Темы: `crates/ps-core/themes/*.json` плюс `~/.1537paperstreet/themes/`
- Кэш диаграмм: `~/.1537paperstreet/cache/mermaid/`
- Состояние UI: `ui-state.json` (раскрытые узлы, ширины панелей, последняя сессия: проект, вкладки документов и их режим, Dashboard, Assistant)
- Логи: `~/.1537paperstreet/logs/app.log`
- История промптов Assistant: `~/.1537paperstreet/agents/prompts.json`
