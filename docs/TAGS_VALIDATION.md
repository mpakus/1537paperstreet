# Tags Cloud validation — T-224

Date: 2026-10-29. Scope: the local development host and synthetic temporary
projects. No user documents were modified by these checks.

## Behavior and source research

The workspace adapts [Bear 2.9](https://blog.bear.app/2026/07/bear-2-9-use-tag-as-workspace/)
and its [tag guide](https://bear.app/faq/how-to-use-tags-in-bear/): simple tags,
closed multiword tags, nested tags, escaped literals, and related-tag scoping.
[Bear's punctuation/numeric migration notes](https://community.bear.app/t/bear-2-beta-update-9695/3582)
also informed closed punctuation/numeric support. This is a Tags workspace,
not an application-wide privacy filter or a full implementation of Bear search.

## Automated acceptance

- Parser regressions cover headings/prose, Unicode/emoji, nested/multiword tags,
  punctuation, numeric closed tags, escaped hashes, forbidden Markdown contexts,
  oversized closed tags, underscore/emphasis boundaries, and label round trips.
- Cross-project tests cover parent deduplication, exact hierarchy boundaries,
  AND intersections, title/path search, cached queries, refresh, removed roots,
  missing folders, symlinks, encrypted-file exclusions, unchanged source bytes,
  pagination, tag truncation, and a folder omitted by the global 5,000-note cap.
- App-state regression resolves a project beyond the first 200 registry entries.
  Session tests preserve the Tags workspace. Existing document-write and
  encrypted-note protections run in the full workspace suite.
- UI regressions cover stale requests, errors/retry, AND selection/reset, opening
  the original project/path, choosing any registered folder, virtualization,
  and keyboard End/Enter access to the last document.
- Mutation check: changing AND to OR in the Rust tag query made the cross-project
  regression fail; the production predicate was restored.

## Browser acceptance

A temporary Vite fixture used JSON generated by the real Rust index over 1,000
synthetic notes in four folders. The temporary harness was removed afterward.

Checked light/dark themes, 1280×800 desktop and compact layout, bounded pane/list
scrolling (800px page with a 555px list), weighted labels, related-tag focus,
document selection, folder selection, counts, error and empty-result states.
The browser console had no errors/warnings. Actual native menu/window behavior,
Windows/Linux GUI, and screen-reader acceptance were not exercised locally.

## Performance

Reproduce with `cargo run --release -p ps-render --example tags_benchmark`.
The fixture creates 1,000 small Markdown notes in four temporary folders. The
baseline is the existing Library scanner with section parsing disabled; the
new measurement adds inline extraction, ancestor expansion and the first cloud
query. Rebuild timings use the median of five runs; cached AND queries use the
mean of 100 runs. These are local measurements, not the PLAN M1 acceptance rig.

Final local arm64 release measurements: baseline scan **158.70 ms**;
tag rebuild **166.45 ms** (+4.9% for extraction/index/query work); cached AND
query **0.31 ms**. The cloud view was tested with 1,000 notes, four folders and
41 distinct tags. The main document-rendering path,
startup, editor input and document writer do not invoke this index. It is lazy,
serialized, off the Tauri command thread, and does not retain source bodies.

## Limits

Global results are explicitly partial at the documented scanner/index caps.
Choose folder rebuilds within that root to recover globally omitted notes.
No release installers, signing/notarization, production upgrade or native
cross-platform manual acceptance is established by these local checks.

## Review and optimization — T-227

Review found and reproduced a same-note navigation bug that could replace an
unsaved editor buffer with disk content, repeated full scans while filters changed
during an in-flight refresh, and missing tags inside underscore emphasis. Numeric
hierarchies now follow Bear's [documented date-tag delimiters](https://blog.bear.app/2017/08/bear-tips-organize-notes-with-tags-and-infinite-nested-tags/),
including YAML-derived cloud labels. Regressions were run before each fix.
The App integration checks cover edit → Tags → reopen → Save, plus a delayed
open of another note after returning to the current draft. Request tests cover
coalescing, refresh during a scan, stale failure retry and unmount cancellation.
Parser checks distinguish enclosing underscore emphasis from underscores inside
tag names (`#_foo_` / `#__foo__`) and verify copied labels round-trip.

A temporary browser fixture held a scan pending while the search changed twice:
only the initial refresh and the final cached query were sent, the cloud finished
loading, and the browser console had no warnings/errors. The fixture was removed.

Final local gates: Rust formatting, Clippy with warnings denied, all **407 Rust
tests** (two existing ignored tests), all **221 UI tests**, Svelte/TypeScript
checks, ESLint, Prettier and the production UI build passed. Independent final
review found no remaining blockers. Existing ts-rs attribute diagnostics,
proc-macro-error2 future-compatibility warning and the Mermaid bundle-size
warning remain documented limitations; this change adds no dependencies.

The query now sorts borrowed count entries and constructs labels only for the
80 displayed tags. The benchmark adds 400 temporary notes containing 100,000
distinct tags, within the existing index cap, and checks identical snapshots on
repeated queries. Three alternating runs of the before/after release binaries
(25 queries per run, median) measured:

| Fixture | Before | After |
| --- | --- | --- |
| 100,000 tags: cached page, run 1 | 18.27 ms | 12.83 ms |
| 100,000 tags: cached page, run 2 | 18.21 ms | 12.89 ms |
| 100,000 tags: cached page, run 3 | 18.25 ms | 12.94 ms |
| 1,000 notes: cached AND query | 0.25–0.26 ms | 0.25–0.26 ms |

The median large-cloud query improved **29.4%** (18.25 → 12.89 ms). The ordinary
fixture's all/focused/folder snapshots were identical before and after in all
three runs. Dedicated pagination coverage also checks frequency order, tie
ordering, weights, project counts and final-page size. No new cache or dependency
was introduced.
